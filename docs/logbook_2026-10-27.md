### 约15m误差的根因与 decoder 后续操作

实际配置 `pts_bbox_head.type='BEVFormerHead'`，运行时实例来自 `bevformer/dense_heads/bevformer_head.py`，有效变换是 `transpose(2,3)+flip(2)`。上一轮诊断取了另一个未激活类 `BEVFormerHead_seg` 的 `rot90(-1)+flip(3)`，等价于仅转置，产生侧向镜像后才得到15.06m。**这是上一轮审计对象错误，不是当前实际模型的15m错误。**

本轮通过真实实例类名、源码路径/SHA、Head的完整 forward、cropper输入输出hook、decoder输入输出hook和XYZ ramp验证。`runtime_chain.json`、`coordinate_evidence.json`、`correction.json` 保留纠正链，旧 `results/lg_bev_20261027/` 的报告完全未改写。

### GPU 优化与拒绝的实现

最初看到的约 41 秒流式测试确有 CPU 插值反向/往返瓶颈。没有更换模型或启用 AMP/FP16；BEV、网络激活、损失及参数保持 FP32，保留原先 CUDA TF32 开关，不额外改变作者数值行为。

严格沿用运行前已登记容差：存储/BEV/原始 Head/相同参数 Attention 前向 max_abs=0；Loss≤1e-5；梯度 max_abs≤2e-5 且 relative L2≤1e-4；更新参数 max_abs≤1e-6。接近零的梯度经过 AdamW 后可能放大成参数差，不能只验梯度总范数。

真实发现并拒绝了如下候选，失败报告全部保留：

1. cuSPARSE 固定网格归约未过参数更新门槛；随后固定 GPU 顺序版本虽在“新路径缓存 vs 新路径重建”上相等，**直接跨旧 CPU 参考的 32 帧检查仍失败**。第一次参数最大差约 3.0164e-5、Loss 差约 5.789e-4，不能宣称原实现等价。
2. 定位到边界重复项 coalesce、CPU AVX2 的 scatter 次序、坐标先乘后除与先求比例之别、半像素坐标 FMA 舍入。修复了固定 grid 的权重/顺序后，小型真实形状算子检查 grid 反向逐位一致；GPU 上采样反向虽约 1e-6 级小误差，但 32 帧累计参数差约 2.0018e-5，仍拒绝。
3. 动态 MSDeform GPU 伴随候选缓存 B32 可到 10.94 秒，但 Loss 差 8.607e-4、参数差 5.836e-6，超门槛；更细的 CPU 顺序兼容候选 33.39 秒且仍失败。动态 CUDA 保留为禁用研究代码，正式入口明确拒绝启用。

最终采用的可靠改动：固定 grid 用 GPU 无 atomic 邻居表线性伴随；仅 CPU 预计算几何权重，模拟 CPU FMA 单次舍入时使用的 double 是辅助坐标计算，不是网络/BEV 转 FP64。上采样继续用**同一个 CPU ATen backward**，直接调用无需输入值的反向内核，去掉巨大输入 D2H 和无用 CPU forward；动态 MSDeform 继续已验证 CPU FP32 参考。合并 scalar/有限值检查，避免逐参数同步；只在真实标定变化时更新位置缓存。

依据 [PyTorch v2.8 CPU GridSampler](https://github.com/pytorch/pytorch/blob/v2.8.0/aten/src/ATen/native/cpu/GridSamplerKernel.cpp)、[CPU Upsample 反向](https://github.com/pytorch/pytorch/blob/v2.8.0/aten/src/ATen/native/cpu/UpSampleMoreKernel.cpp) 及本机对应头文件核查运算次序；结论最终以真实 32 帧数值验收为准，没有依赖源码推测直接放行。
