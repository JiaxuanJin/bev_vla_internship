## 7. 新正式测试的候选方案与授权边界

后续研究的关键证据缺口是**原任务 DriveLM-v1 测试集上的同协议 Baseline/增强成对感知结果**。拟议前提与计算量如下，供另行决策：

- **数据身份：** 固定 DriveLM-v1 发行来源/版本/SHA、官方 test split 与 nuScenes token/scene 映射、可合法取得的评分 GT 和指令到真实空间目标的定义。现有本地记录是 696 场景/4072 关键帧/29450 条训练 QA 预处理及不同协议的 799 帧历史视觉基线；它们不自动成为 test。正式测试帧数 N、有效指令数 Q 当前均 NOT_VERIFIED，规模尚待确认。
- **测试范围：** 冻结作者 Baseline 与 StageB256，A9562 作为空间-only 控制；同输入、时序、GT、候选框、匹配和区域协议。只读已训练权重，不恢复原正式 run、不训练，不用结果选择新阈值。需先确认这些定义确实对应原始正式 mAP/mIoU 与整体指标。
- **计算量/资源：** 约为 N 帧共享 BEV 构建，加各组在 Q 条 query 上的 Head/Adapter 前向与指标累计；实际 GPU 时长、峰值显存和存储在 N/Q 与缓存方案未冻结前均 NOT_VERIFIED。历史 8 帧时耗和旧 320 帧预估仅供历史资源参考，正式测试预算需独立测量。需要固定 GPU 会话/预算/输出根与数据权限后另行批准；资源预算尚未通过探针测量验证。
- **预期价值：** 获得原始正式测试的可比结果，即使仍为负向也可补足覆盖；不能保证模型因此达标。若测试 GT 无法取得，须记录不可评价原因，而非用 8 帧或 Development 替代。
- **独立 Development：** 既定 320 帧/640 query/三组方案的数据规模已登记，但 v2 新源码与协议 SHA 必须单独授权，不能从 v1 失败会话直接 resume；即使完成，也仅补充 Development，不能完成 T4-01。RTX 3090 延迟还需要该实际设备及独立计时协议，现有 5080 数据不替代。
