## 2. 数据来源与统计方法

新增内容限于：分场景表的可读导出、已有逐 query 背景项的导出，以及尚缺的“任务×类别×限定词”分组。后者只对同协议存储标量求算术平均；不平均不同场景 AP 来代替全局 AP，不混合 A128 与 8 帧，不混合地图与对象网格。输入 SHA、字段来源、分母及输出摘要见[来源与统计口径](../../results/stage4_delivery_20261103/来源与统计口径.json)；整理入口为[只读整理脚本](../../scripts/stage4/summarize_existing.py)。没有读取 GT、Checkpoint、Cold Final 或重新加载原始预测二进制。

Attention 以有效域内 Logit ≥0（sigmoid ≥0.5）为激活；正目标 macro IoU 按 query 等权，空目标不进入该均值，空目标激活率单列。`background_FP` 和 `distractor_FP` 是 Attention 激活**像素**数，不能称作检测框误检数。无正类或无有效配对的指标记 **NOT_VERIFIED**，同时在 CSV 保留来源的 `NOT_EVALUABLE`；不补零、不删场景。

## 8. 技术解释、原始目标与后续工作

已验证的阻断表现是空间重叠不足、背景扩散、同类干扰及下游收益不足。类别监督不能区分同类空间目标；真实实例/区域 GT 和反事实监督解决了监督定义，却没有保证优化后的定位准确。历史 V5 中任务梯度冲突及冻结 Head 输入分布扰动有记录，作为 StageB256 的解释仍属待检验假设；小样本、正例不平衡与检测损失/排名指标不同也不足以确立唯一因果根因。

后续方向是在未来独立授权的研究中检查正/背景平衡、同类难例、空间分辨率与多任务梯度协调，并先固定同协议充分样本的评价；后续研究应采用预先冻结的单因素对照，保持版本、预算和阈值可追溯。

| 原始基本性能目标 | 正式状态 | 证据与限制 |
|---|---|---|
| 指令相关目标 3D 检测 mAP 提升 ≥2% | **NOT_VERIFIED** | DriveLM-v1 正式测试 NOT_RUN；8 帧自定义 AP 无增益，不能替代正式 mAP |
| 指令相关区域 BEV 分割 mIoU 提升 ≥1.5% | **NOT_VERIFIED** | 8 帧区域分割仅约 +0.0230 个百分点，非正式测试达标证据 |
| 整体平均精度下降 ≤2% | **NOT_VERIFIED** | 无关区域分数不是完整整体平均精度；正式综合约束未评价 |
| RTX 3090 单帧额外延迟 ≤20ms | **NOT_RUN / NOT_VERIFIED** | RTX 5080 Laptop 的历史计时不能替代 3090 实测 |

任务目标采用登记的百分比写法；诊断变化量明确使用百分点。结项按完整技术闭环交付，正式性能缺口继续保留。
