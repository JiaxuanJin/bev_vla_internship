# 第二阶段执行计划｜语言引导的 BEV 注意力增强模块

周期：2026-10-20 至 2026-10-23（10 月 23 日截止）  
实现目标：在已有 BEVFormer 特征提取基础上，完成语言编码、语义空间映射、注意力融合、多任务损失和可运行的最小集成系统。

## 1. 架构与接口

```text
自然语言指令 -> tokenizer -> DistilBERT -> 文本特征 (B,L,D_text)
                                         |
                              语义-空间映射头
                                         v
                                  BEV 引导特征
                                         |
六路图像 -> BEVFormer Backbone -> BEV 特征 (B,C,H,W)
                                         |
                             空间注意力生成/融合
                                         v
                                 Enhanced BEV
                                         |
                           原检测/分割头与损失模块
```

建议的首版接口：`text_tokens: (B,L)`、`text_mask: (B,L)`、`bev_features: (B,256,150,150)`，输出注意力图 `attention_map: (B,1,150,150)` 与增强特征 `enhanced_bev: (B,256,150,150)`。`D_text` 以实际下载的 DistilBERT 配置为准；不把示意尺寸当作已测结果。

注意力起始实现采用简单、可测试的语言条件空间门控：文本池化 → Linear 到 256 维 → 与 BEV 投影后的各位置特征计算相似度 → sigmoid 注意力 → 残差融合 `BEV + α × (BEV × attention)`。门控残差系数 α 初始化为零或很小，先保证未训练模块不会直接破坏原模型输出。复杂 Cross-Attention 留作扩展，不阻塞阶段验收。

## 3. 实施原则与范围限制

- 优先交付**能够实际运行和测试的最小系统（MVP）**，避免将大规模重训练作为 4 天内的必达项。
- 若现有数据只有分割标签，检测损失仅在确有检测真值与模型输出时启用；不能虚构检测/语言任务的训练指标。
- 初期冻结 DistilBERT 和 BEVFormer 主干，只训练映射和融合层；确认梯度链后再评估是否允许部分解冻。
- 语言引导注意力的监督信号应明确定义；缺乏对应标注时采用可解释的正则项、合成指令或可视化检查，注明限制。
- 第一阶段前景 mIoU 低分作为已知基线问题，在阶段二对比时保持同权重、同输入、同评价条件；不能把未收敛的增强模块引起的指标变化归为有效提升。
