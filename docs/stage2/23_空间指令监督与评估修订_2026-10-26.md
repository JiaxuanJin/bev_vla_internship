# 第二阶段补充：指令级空间监督与相关区域评估（2026-10-26）

## 1. 已知缺口与边界

- 当前 `multitask_training.supervised_attention_loss` 的旧分支使用 `GT == target_class`，监督整张地图中的同类元素；这不能证明模型关注的是指令指定的某个位置或实例。
- 指令解析已有有限方向词，BEV 网格与 LiDAR→Ego 坐标转换已有基础。但 `150×150 BEV` 与 `200×400 GT` 并非可直接互换的像素网格。
- 根目录 `stage2/` 是早期兼容包；`scripts/stage2/` 是主要实验代码，且 `run_stage2.py` 读取 `stage2/tokenizer_config.json`。重名模块不等于完全重复，需审计依赖后再考虑精简。
- 本补丁提供可测试的**空间监督和分项评价接口**；不宣称已有真实实例标签、不声称真实训练已成功或检测精度已提升。

## 2. 标签协议：从类别监督到实例空间监督

每一帧、每条指令需要独立于模型预测准备以下标注：

| 字段 | 要求 |
|---|---|
| `instruction_id` | 全局唯一，训练与 A/B 测试可以严格一一对应 |
| `target_class` | 已验证的 1/2/3 地图类别 |
| `instance_id` | 具体地图元素实例/目标 ID，**不能只是类别名** |
| `instance_mask [H,W]` | 对齐原始分割 GT 的该具体实例的布尔像素掩码 |
| `related_region [H,W]` | 对齐原始分割 GT 的指令空间区域，由外部标注的 ROI/多边形或经验证物理投影生成 |
| `annotation_source` | 数据集实例标注或经检查的人工标注；禁止以 `GT == class_id` 冒充实例 |
| `coordinate_frame` | `segmentation_gt_pixel_grid`；禁止直接将 `150×150` 方向掩码 resize 成 GT 标签 |

方向词（front/rear/left/right）由 Ego 坐标表达，但把其变成 **GT 像素网格上的 ROI** 需要明确的物理配准契约。没有完成这一步时应保留 `NOT_VERIFIED`；不能悄悄假设图像上方就是车辆前方。

仅使用 `class ∩ front_right` 只能约束象限；如果一个象限内有多个同类目标，仍然不能区分实例。此时必须使用实例 ID/显式 ROI 指代，歧义样本不能训练为“唯一实例”。

## 3. 增量代码清单

- `scripts/stage2/spatial_supervision.py`：目标实例标签合法性校验、正例加权 BCE + Soft Dice；同类非指令目标作为负例。
- `scripts/stage2/instruction_metrics.py`：相关/无关 ROI 四类分割混淆矩阵及 IoU；目标实例注意力 IoU、注意力质量集中度、同类干扰物质量比。
- `scripts/stage2/instruction_detection_metrics.py`：按真实 3D 检测器**外部输出的匹配结果**累计相关/无关区域 AP 代理量；不等同 nuScenes 官方 mAP。
- `scripts/stage2/audit_layout.py`：只读检索重名代码、导入依赖和配置文件引用。
- `scripts/stage2/apply_spatial_patch.py`：为历史 `multitask_training.py` 增加可选 `spatial_targets=` 接口；不传时完全保留旧类别监督，便于回归。
- `tests/stage2/test_stage2_spatial_supervision.py`：不需要作者权重的 CPU 测试。

## 4. 使用方式（在仓库根目录）

1. 解压补丁文件，确保新增脚本位于 `scripts/stage2/`，文档位于 `docs/stage2/`，测试位于 `tests/`。解压前先执行 `git status --short`，不得覆盖现有修改。
2. `python scripts/stage2/audit_layout.py`。
3. `python scripts/stage2/apply_spatial_patch.py`：只检查历史源码锚点、Git 修改状态；**不写入任何文件**。
4. 检查通过后 `python scripts/stage2/apply_spatial_patch.py --apply`：保存原文件备份到 `.git/` 后扩展接口。
5. `python -m pytest -q tests/stage2/test_stage2_spatial_supervision.py tests/stage2/test_stage2_pipeline.py`。
6. `git diff -- scripts/stage2/multitask_training.py`，再决定是否提交。不要对历史 61/64/72 实验重新命名为“空间训练”。

启用空间监督的调用示例（伪代码，需有**真实标注**，不能用合成掩码代替真实实验）：

```python
loss, parts = Stage2MultiTaskLoss(config)(
    real_detection_losses,
    segmentation_logits,
    gt_segmentation,
    attention_logits,
    target_classes,
    spatial_targets=verified_spatial_targets,
)
```

## 5. 本周真实验证前必须补齐的输入

- 对现有 Mini/val 帧检查可否提取指令目标对应的**实例 ID 与区域标注**，没有实例 ID 时建立一份可复核的精简人工标注清单；训练/验证按 scene 切分。
- 每份标注单独核对 target mask 与 GT 一致性、ROI 的几何来源、像素与物理坐标约定；不使用预测 attention 来生成监督目标。
- A/B 实验需要固定指令文本、样本 token、GT、ROI、检查点、阈值和相同的官方检测匹配协议。报告相关/无关区域的分类指标变化，并区分指令定位收益与全域背景变化。
- 3D 检测要用真实 box/距离阈值官方匹配生成输入；地图三类别 IoU 不能替代车辆/行人/骑行者 3D detection AP。
- 新损失只有接口与合成梯度通过时记为 `PASS_CPU_UNIT_ONLY`；真实标注训练和 held-out A/B 未完成应记为 `NOT_VERIFIED`。

## 6. 风险记录

1. 类别标签不含唯一目标归属；象限裁剪只做区域筛选，不能在同区域多个实例时唯一定位。
2. 语义地图可能是细线且不连通，不能无验证地用 connected components 冒充真实实例 ID。
3. ROI 内只计算 GT 正像素会隐藏假阳性，因此评价必须使用**包含背景与干扰物的整个独立 ROI**，并另算 ROI 外指标。
4. 当前接口不自动修改 `joint_runtime.py` 或启动新的真实训练；需要数据标签准备与集成阶段完成后才能评估精度收益。
