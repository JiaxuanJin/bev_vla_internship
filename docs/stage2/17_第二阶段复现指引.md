## 冻结旧20步实验版本的只读重放

当前源码增加TV/文本一致性/协议配置恢复后，原协议的绝对源码哈希会主动拒绝在当前根目录直接恢复。原40个源码文件保存在 `results/stage2_final_audit_2026-10-22/legacy_source/scripts/stage2`，逐文件哈希与原协议一致。请使用可执行入口：

```bash

PY=~/projects/bevformer_author_clean_5080/.venv-author/bin/python
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 PYTHONDONTWRITEBYTECODE=1 \
  "$PY" -u scripts/stage2/replay_stage2.py \
  --output outputs/new_frozen_replay/result.json
```

本轮已实测重放：全部6帧所有数组及指标精确相同，0次更新，详见legacy_replay_summary.json。

verify-only只校验冻结源码与旧最终权重。重放入口只允许旧第20步的validate，不允许训练；新进程从冻结源码真正导入模块，将原协议中源码地址的哈希读取重定位至已逐文件验证的快照，保留原数据/模型/配置/协议原文哈希校验，并继承宿主内存watchdog。不会放宽当前入口的源码一致性约束，也不编辑旧协议。第20步融合SHA256 `125237365f3b456384009168ad8b97df6f0e46805331f79c7e1c344d4c2e9d5a`。

旧协议绑定原机绝对数据/模型路径。换机器需要准备相同资产并明确适配路径，不能静默改写原协议后仍声称同一哈希实验。CUDA算子未强制逐位确定，重跑差异需按真实数值记录。

跨机器新smoke可通过 `--author-root`、`--joint-config`、`--joint-checkpoint`、`--model` 指定本机资产路径；旧历史协议的绝对路径与哈希不能伪造重写。复现实验和源代码可搬运性是两种不同边界。

## 新实验入口（仅说明，本轮不执行训练）

新实验必须另建协议和输出目录。`--micro-phase step --attention-tv-weight 0.001` 固定20个train/6个val、先运行且只运行1次更新；后续显式 `--micro-phase continue --micro-steps 19 --protocol 新协议 --resume 新step001 --output 新续训目录/run.json`，恢复optimizer与协议损失配置。只有总第20步才能 `--micro-phase validate`。默认TV=0保持历史行为，不能通过CLI改写已有协议损失配置；不可将有TV的新实验冒充旧结果。
