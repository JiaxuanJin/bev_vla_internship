# 2026-10-20 实验记录｜BEVFormer 分割低 IoU 独立复现与空间协议核验

## 1. 今日目标

围绕第一阶段地图分割前景 IoU 偏低的问题，继续核查评估协议、空间方向、真实标定、原始模型运行环境以及训练/推理空间约定。在不覆盖原始 checkpoint 的前提下，建立可追踪的低分基线，检验候选修复是否能在独立验证场景稳定提升。

## 2. 完成工作

### 2.1 评估协议与方向候选审计（Step 37–46）

- **Step 37**：官方 Val 12 帧独立推理，`original_ccw90`、`transpose_candidate`、`lidar_to_ego_grid` 的前景 mIoU 分别为 **7.59%、14.28%、8.05%**。该实验不包含连续时序，不能与完整 Val 或 Mini Val 时序结果直接比较。
- **Step 38**：官方 Val PKL 为 **6019 帧、150 个场景**；sample token 无重复；PKL 与 Step 34 使用版本哈希一致。作者的前景 mIoU 公式按全局混淆矩阵重算一致。Step 34 的原始 mIoU 为 **4.6416%**，历史 JSON 字段 `physical_ccw_candidate` 实际为 **Transpose** 候选，其 mIoU 为 **19.6000%**，目前不能视为正式修复。
- **Step 39**：固定方向候选在 screen/verify 组分别达到 **20.471% / 21.978%**，但在 regression 组降至 **5.761%**，说明方向候选跨场景效果不稳。
- **Step 40**：训练集监督的 decoder A/B 试验完成，但实际使用的训练 PKL 是 **v1.0-mini，323 帧、8 场景**，并非完整 trainval。15 帧无时序验证属于诊断试验，不可作为正式 Val 基线或“修复完成”的依据。
- **Step 41**：基于真实 LiDAR→Ego 标定建立坐标映射检查，合成 XY 坐标场数值一致性通过；仅说明坐标变换数学实现正确。
- **Step 42**：作者 `single_gpu_test` 与本地手动评估在同样 30 帧上的 mIoU 一致（差异约 0.000002），说明当前观察到的巨大差距不太可能仅由指标公式造成。
- **Step 43**：按公开讨论调整 `map_y` 取样方向，Mini Val 81 帧时序前景 mIoU **6.3756% → 6.4051%**，无法解释与作者约 40% 的差距。
- **Step 44**：GT 翻转与类别置换搜索，在一个场景中优选的 GT 空间变换在另一场景的指标下降，未找到可跨场景稳健改善的简单变换。
- **Step 45–46**：检查 CUDA 运算数值与图像投影运行路径。3 帧相机投影审计中，任一相机可见的 BEV query 占比约 **99.8%**，非有限投影值为 0；LiDAR 点云投影到六路相机原图的叠加可视化已保存。该检查不能代替完整网络和 GT 正确性证明。

### 2.2 独立作者环境建立与原始 Mini Val 复现（Step 47–50）

在 `~/projects/bevformer_author_clean_5080/` 建立隔离工程，在 RTX 5080 Laptop GPU 上使用 PyTorch 2.8.0+cu128、CUDA 12.8、MMCV 1.4.0、MMDetection 2.14.0、MMDetection3D 0.17.1 和 MMSegmentation 0.14.1 完成运行兼容性适配。MMCV CUDA 扩展和 MMDetection3D CUDA 测试通过；旧版 MMCV 的 GPU scatter 因新版 PyTorch 接口发生不兼容，在隔离环境进行了小范围设备参数兼容修正。该环境保持作者分割模型核心源码，但不是作者发布时完全一致的历史依赖组合。

**Step 50**：使用作者的 `single_gpu_test()`、公开分割 checkpoint、Mini Val 全部 81 帧、时序开启，最终前景 **mIoU 6.38%**，Divider **2.23%**、Pred Crossing **8.73%**、Boundary **8.17%**。与工作环境的约 6.38% 基线接近，排除了“只有旧工作环境修改才产生低分”的简单解释。

### 2.3 训练/推理空间协议与真实模型验证（Step 51–54）

| 步骤 | 试验 | 结果 |
|---|---|---|
| 51 | 比对 checkpoint 保存的训练 Config、作者环境、工作环境中的空间字段与关键函数 AST | 所比较字段及 11 个关键函数一致；无法证明训练时实际 git commit 相同 |
| 52 | 作者真实 BevFeatureSlicer + Mini 标定传递合成 XY 坐标场 | Mini 第 0/40/80 帧平均平面误差约 0.9858 / 0.9445 / 0.9445 m |
| 53 | 真实 LiDAR→Ego 标定下的合成 XY 坐标校正 | 上述偏差降至数值精度内约 0，不涉及网络前向 |
| 54 | 冻结同一 checkpoint、相同 81 帧、开启时序的模型 A/B | baseline **6.38%**、calibrated **5.76%**，下降 **0.62 个百分点** |

Step 54 分类别结果：

| 分支 | Divider | Pred Crossing | Boundary | 前景 mIoU |
|---|---:|---:|---:|---:|
| baseline | 2.23% | 8.73% | 8.17% | **6.38%** |
| calibrated | 2.18% | 7.11% | 7.97% | **5.76%** |

**结论**：在合成坐标场中可校正的约 1 m 物理差异，并未在真实模型上带来 IoU 改善。不能把该纯推理端平移补偿作为最终修复，暂不修改正式推理分支。

## 3. 当前判断

1. 低前景 IoU 已在两套独立的运行环境中稳定复现：Mini Val 时序 **约 6.38%**；不宜继续把问题归因于单一工作环境损坏。
2. 当前静态配置与关键空间源码一致；但 checkpoint 配置元数据无法证明历史训练时执行的源码版本。
3. 部分 Transpose 候选在局部样本显著提升，另一部分场景退化；不能据此得出跨场景普适的方向修复结论。
4. Step 54 的真实模型 A/B 否定了“单独添加当前 LiDAR→Ego 平移校正即可恢复高分”的假设。
5. 作者报告的约 40% Mini Val 指标尚未复现，主要待核实项是**高分实验的完整 checkpoint/训练源码/GT 地图版本及测试协议**是否与当前一致。

## 4. 下一步与风险

优先确认作者高分实验对应的训练代码提交、权重与完整运行命令；只读比对 Mini Val PKL、nuScenes 地图版本、GT 栅格和预测结果同点位对应关系。确认具体约定后再实施最小修复，并用两个 Mini 场景和完整 Val 6019 帧验证三类 IoU 是否稳健改善。正式修复前，继续保留原始 baseline、已发现的失败 A/B 和未经合入的方向候选。
