## 三、Stage B 核心组件是否可用

**核心前向/反向已经存在；本次A权重迁移、新评估和新数据入口尚待实现与验收。**

现有路径是：六相机时序BEV → 冻结原生BEV → 语言Adapter的受限残差 → 同一增强BEV
进入冻结Detection/Segmentation双Head。文本来自冻结DistilBERT readout，position只来自
标定。所有分支共用未增强的时序history，不能把enhanced BEV写回history。

已有证据：同当前33源码绑定的V3 B32工程验收覆盖真实前后向、8次更新、跨进程恢复，
loss/梯度/参数差为0，Head/BN冻结。较早engineering验收还记录：零up初步任务梯度到up，
上游language任务梯度为0；后续det/seg的language梯度分别约0.002912/0.000195。
这些是小样本工程证据，不能替代当前A9562迁移后的检查或泛化结果。

现有B损失可复用，不在本轮改权重：

`L_det + L_seg_native + 0.2 L_attention + 0.1 L_pair + 0.5 L_map_roi + 0.1 KL_seg_outside`

- Detection保留作者Hungarian和全GT；目标matched positive的cls/bbox权重×3。
- Segmentation保留作者CE及内部类别权重/Loss权重；地图目标2m ROI另加CE。
- KL保护非相关区分割分布；对象任务保护区按指令象限，地图按2m目标ROI。
- 只有分割有显式无关区KL；不能把它说成已经保证了无关区域检测性能。
- 保持作者模型/双Head/BN和文本模块eval且requires_grad=false；Head前向必须保留
  对输入BEV的计算图，不能用no_grad把学生分支切断。teacher分支才使用no_grad。

独立B从A Checkpoint只读加载 `state_dict`，strict=True，核对源SHA、架构、维度及
零up；新建AdamW、scheduler、RNG、预算和run-id。**不能调用原Trainer.resume(A)**：
它绑定stage、tokens、budget、execution及优化器；也不能把A的9562步当成新B步数。
不修改 `full_training()` 的A128闸门，不调用原正式start/resume/evaluate_terminal。

## 五、统一评估协议与具体缺口

现有 `functional_audit()` 提供related conditional AP、overall AP、related ROI IoU
与overall IoU；**没有独立的irrelevant AP/IoU**，也没有三checkpoint统一入口。
不能用overall减related来计算irrelevant AP/IoU，不得将全局保护指标改名为无关区域指标。

### 四项区域主指标

为避免nearest/farthest指令的目标集合与纯象限区域混淆，主区域Detection协议仅使用
固定表中的“all cars/pedestrians in quadrant”指令。nearest/farthest的实例定位能力
另用既有conditional AP报告，二者不得混名。

| 指标 | 固定定义 |
|---|---|
| Relevant Detection AP | 请求类别在正确指令Ego象限内的GT及预测中心；car/pedestrian按0.5/1/2/4m中心距离分别AP再宏平均 |
| Irrelevant Detection AP | 同一请求类别、相同有效检测范围内的象限补集；GT和预测采用完全相同的独立空间规则 |
| Relevant Segmentation IoU | 正确地图指令的真实目标record mask扩张2m，与有效Ego网格相交；完整语义GT计混淆矩阵，lane/crosswalk按类汇总后宏平均 |
| Irrelevant Segmentation IoU | 同一地图query有效网格减上述ROI；使用同一完整GT和lane/crosswalk类集合，直接累计独立混淆矩阵 |

检测分区须先将预测和GT中心都转到Ego，不得拿LiDAR正负号直接解释前后左右。
边界x=0/y=0预先归入front/left，形成无重叠完整分区；每个query每个预测仅归入一侧。
跨边界盒按中心归属，边界附近可能造成FP/FN，保持所有组同规则并披露。
预测不按是否接近GT而预筛选；不做阈值搜索，保持原native top300及SDK类距离/零点GT/
bicycle-rack过滤；score全局排序。按query在分区内匹配，再跨query按类计AP。

这四项是**自定义独立子集区域指标**，不是nuScenes官方全val mAP。检测主指标覆盖
有指令支持的car/pedestrian两类，不能声称10类均受语言区域评估。
同时补报全10类全图AP、全3前景类IoU、旧实例conditional AP及同类干扰FP，避免
区域改善掩盖全局退化。AP采用现有SDK口径；分区的定义和边界属于新协议。

空目标query保留预测FP；无正GT的整类AP标NOT_EVALUABLE，不以0或删除该类替代。
空地图目标的相关ROI为空，相关IoU为N/A，另报误激活；无关ROI为完整有效域。
新scorer显式报告GT正例数、union、query数、像素数和缺失原因；现有macro_iou注释
声称检查缺正类，但实现仅检查union，需在新版本中明确修正该语义，不动旧结果。

### 指令表、控制与统计

每评价帧固定1条object-all和1条map指令，共640条query，按类别轮换与hash取方向/
地图可用指令，规则先登记；保留空目标，不依据模型表现选正例。
GT覆盖审核在预测前完成；若缺主指标正类，只可按预登记规则扩展为每日志4场景
（最多640帧），不得看结果再补“有利”帧。仍缺类别则如实NOT_EVALUABLE。

三组以及correct/wrong/zero输入共享同一query表、正确GT、ROI、过滤、匹配、聚合。
wrong文本仍按正确指令评分；wrong自身目标集合仅用于额外诊断，不能替换主评分GT。
保留每场景及驾驶日志结果；对组间差值做配对场景/日志cluster bootstrap，而不是
把同帧多指令当独立样本。仅5个独立日志，置信区间与显著性须保守解释；不承诺提升。

| 依据 | 现有记录 |
|---|---|
| 当前源码B32纯参考训练 | 18.24秒/32微步≈0.57秒/微步，来自已缓存小样本 |
| 当前源码跨3场景流式B32 | 100.93秒/32≈3.15秒/微步；最大单步20.09秒 |
| 原生生成/场景启动 | 既有估计0.467秒/帧、后续epoch场景启动14.43秒；只是小样本依据 |
| 真实正式A日志 | 微步median 0.0336秒、p95 16.21秒、mean 2.464秒；长尾来自缓存/场景/I/O |
| A累计时间 | session_end累计约39.25小时；微步计时合计约26.18小时，二者不能混用或外推纯GPU算力 |
| B32峰值 | CUDA allocated约1.88GiB；历史reserved最高约3.25GiB、进程RSS约4.95GiB；不是新子集峰值承诺 |
| 当前G盘 | 空闲约360.19GB；沿用至少250GB空闲要求 |
| 既有缓存根目录 | 约20.28GB；30GB上限剩约9.72GB；目录中verified shard约9.45GB |

主训练1024微步按流式3.15秒约0.90小时；按8秒/微步保守假设约2.28小时。
再计初始化、checkpoint、scene构建与长尾，**主训练安排1.2–3小时**，单会话仍保留
提前保存窗口。0.57秒/微步不能用作全流程承诺。

建议最小一次种子完整闭环预留 **6–10小时GPU占用/会话墙钟预算**：

- 新A权重迁移/连续时序/双Head梯度/停止保存预检：0.5–1小时；
- 必要原生特征再生、开发子集数据准备及初始化：0.5–1.5小时；其中部分为CPU/I/O；
- 主B训练：1.2–3小时；
- 三组四项指标、正确/错误控制及初始/A定位：1–2.5小时；
- 保留约1–2小时失败定位/中断恢复余量。

评估估算尚未实测：320个native帧、640个query，至少需要640×2个Enhanced
correct/wrong双Head前向，Baseline约320次；zero-text增加640次。A Only输出在确认
恒等后复用Baseline，否则还需额外前向。因此GPU预检必须测端到端吞吐并重新核算，
不能把上述范围写成保证时长。多seed可选，11月7日后不再加训练分支。

FP32原生BEV为23.04MB/帧：512训练帧约11.80GB，320评估帧约7.37GB，合计19.17GB，
超过当前缓存上限剩余空间。采用分场景8帧分片、活动缓存约1.5–2GB；在全新G盘目录
设置新增全部实验资产≤8GB，并同时检查既有+新增总量≤30GB、G盘空闲≥250GB。
不自动清理旧缓存/Checkpoint，不更新原catalog访问或淘汰记录；有效旧shard只读核验复用。
仅保存轻量预测、混淆矩阵/AP事件与固定少量可视化，不保存全部多分支float logits；
训练GT不复制，development只生成所需子集标签。未命中缓存按重建计预算，不假设命中。

回退规则必须在独立评价前确定：

1. **预检吞吐/时间不够**：改用预登记的训练候选前8场景×32帧×1 epoch，64更新，
   新schedule T_max=64，固定终点；保留同一320帧评价与四项指标。明确它是缩小探索预算，
   不修改原正式预算。若主256方案已开始，不从若干中间checkpoint挑最好；按实际完成
   步数标INCOMPLETE或另行批准独立短预算重跑。
2. **B稳定但效果无提升**：交付Baseline/A Only/B Enhanced的完整负结果，分析语言定位、
   残差容量使用、目标覆盖及无关区损害；不扩大5%上限、解冻Head、换阈值或重用A128调参。
3. **迁移梯度、GT坐标、数值或冻结不变量失败**：停止B并保留错误证据。交付A前后定位和
   Baseline/A Only对照，明确“训练后B Enhanced完整对照”交付项尚未完成，不能拿
   无效B或A Only改名冒充。
4. **无独立评估授权/标签未就绪**：仅训练内功能对照，标明A已见数据；不声称泛化。
5. **空间/显存不足**：先减少活跃分片、顺序处理分支、CPU流式计分；不买盘、不删除旧证据、
   不降低FP32精度或未经登记缩小图像。仍不足则采用预登记短预算/停止，并披露限制。

最终报告须分清：A128正式验收失败；后续独立探索是否可运行；新区域指标是否可计算；
是否存在统计和实际收益。根因区分已验证事实与假设；不保证短B一定改善。
局限至少包括：GT派生模板而非自由语言、仅两类区域检测/两类目标分割、A失败迁移、
单seed小子集、仅5个独立评价日志、可能道路/地图重叠、自定义区域口径、冻结Head和
5%残差约束、作者预训练可能已见原nuScenes train中的评价帧，以及未开启Cold Final。
